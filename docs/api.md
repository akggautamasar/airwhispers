# AirWhispers API (v1)

Base URL: `https://your-server` — every route below lives under `/api/v1`, except the two
health probes. All bodies are JSON; all timestamps are ISO-8601 strings in responses and
epoch-milliseconds internally.

**Identity in one sentence:** a *device* registers once and receives a short random `code`
plus a long-lived `deviceSecret`; the secret buys fresh access tokens forever, and the code
is the only address a friend needs. There is no email, no password and no account recovery.

```
POST /api/v1/device/register ──► { user.code, tokens, deviceSecret }   (first launch)
POST /api/v1/device/token    ──► { user, tokens }                      (silent refresh, forever)
```

## Errors

Every failure uses one envelope:

```json
{ "error": { "code": "bad_request", "message": "A code is 6 characters, like k7m2pq",
             "retryAfterMs": 4200 } }
```

| HTTP | `code` | Meaning |
| --- | --- | --- |
| 400 | `bad_request` | Validation failed (the message says what) |
| 401 | `unauthorized` | Missing/expired token, or an unknown device secret |
| 403 | `forbidden` | You are not a member of that conversation, or the server is closed to new devices |
| 404 | `not_found` | Unknown code, conversation or message |
| 409 | `conflict` | Could not allocate a free code (retry) |
| 429 | `rate_limited` | Slow down; `retryAfterMs` says how long |

Authenticated requests use `Authorization: Bearer <accessToken>`.

Rate limits (fixed window): device registration 60/min per IP, token 120/min per IP,
forget 10/min per IP, opening a chat 60/min per device, sending 120/min per device,
consent changes 60/min per device.

## Device identity

### `POST /api/v1/device/register`

```json
{ "deviceId": "8f4c…", "displayName": "Anu", "platform": "android", "appVersion": "1.0.0" }
```

* **Without `deviceSecret`** → mints a new identity. `201`:
  `{ user: { id, code, displayName, createdAt }, tokens: { accessToken, expiresIn, tokenType },
     deviceSecret: "…" }` — the secret is returned exactly once.
* **With `deviceSecret`** → resumes the identity that owns that secret. `200`, same body
  without `deviceSecret`. A wrong secret is `401`.

`deviceId` is generated by the app per installation. Codes are 6 characters from
`abcdefghjkmnpqrstuvwxyz23456789` (no `0/o/1/l/i`), stored lowercase, compared
case-insensitively, and normalised from whatever a human types (`K7M-2PQ` → `k7m2pq`).

### `POST /api/v1/device/token`

```json
{ "deviceId": "8f4c…", "deviceSecret": "…" }
```

`200 { user, tokens }`. This is the whole "login" of the product: no UI, no user input.

### `POST /api/v1/device/forget`

```json
{ "deviceId": "8f4c…", "deviceSecret": "…" }
```

`204`. The credential is deleted; the next `/device/register` without a secret hands out a
**new** code. The old identity keeps its messages but can no longer be reached at that code
by this device.

### `GET /api/v1/me` · `PATCH /api/v1/me`

```json
{ "user": { "id": "…", "code": "k7m2pq", "displayName": "Anu", "createdAt": "…" } }
```

`PATCH` accepts `{ "displayName": "Anu (work)" }` and broadcasts `peer.updated` to everyone
who shares a conversation with this device.

## Chats

### `GET /api/v1/conversations`

```json
{ "conversations": [ {
  "id": "…",
  "createdAt": "…",
  "peer": { "id": "…", "code": "b4x9tt", "displayName": "Bob", "createdAt": "…", "online": true },
  "lastMessage": { "…message…" } ,
  "unreadCount": 2,
  "youAllowSpeak": true,
  "peerAllowsSpeak": false
} ] }
```

* `youAllowSpeak` — *this* device lets that peer's messages be spoken aloud here.
* `peerAllowsSpeak` — that peer lets *this* device's messages be spoken there.
* `online` comes from the realtime hub, not the database.

### `POST /api/v1/conversations`

```json
{ "code": "k7m 2pq" }
```

Opens or re-opens the 1:1 chat with the device that owns the code. `201` with
`{ conversation }`. `404` when no device uses that code (checked *after* normalisation),
`400` when the code is malformed or is this device's own code.

### `PATCH /api/v1/conversations/:id/trust`

```json
{ "trusted": true }
```

Speech consent, **owned by the listener**: only the device being spoken to can set it. The
other side is notified with `peer.updated`. `200 { conversation }`.

## Messages

### `GET /api/v1/conversations/:id/messages?limit=100`

```json
{ "messages": [ {
  "id": "…", "clientMessageId": "…", "conversationId": "…",
  "senderId": "…", "recipientId": "…", "text": "Are you alone?",
  "createdAt": "…", "priority": "NORMAL" | "SPEAK_NOW",
  "deliveryStatus": "sent" | "delivered",
  "readStatus": "unread" | "read",
  "spoken": false,
  "speakEligible": true
} ] }
```

`limit` is clamped to 1…200. Fetching history marks the caller's incoming messages as
delivered. `speakEligible` reflects the current consent (`recipient allows sender`).

### `POST /api/v1/conversations/:id/messages`

```json
{ "clientMessageId": "0e1b…", "text": "Are you alone?", "priority": "SPEAK_NOW" }
```

* `201` on a new message, `200` when this `clientMessageId` was already sent (idempotent
  replay — safe for retries; the original message is returned).
* `priority: "SPEAK_NOW"` is a *request*: the recipient's Call Assist may speak it
  immediately instead of waiting for the next call, but the recipient's consent and local
  rules always win.
* Delivery: every open socket of both devices receives `message.created`. Devices that are
  offline and registered a push token get a data-only FCM message (ids and metadata only
  unless `PUSH_INCLUDES_CONTENT=true`).

### Receipts

| Method | Path | Who | Effect |
| --- | --- | --- | --- |
| `POST` | `/api/v1/messages/:id/read` | recipient only | Marks the conversation read, broadcasts `message.read` to the sender |
| `POST` | `/api/v1/messages/:id/spoken` | recipient only | "my phone actually read this aloud" → `message.updated` |

Both return `204` and accept an empty body.

| Method | Path | Body |
| --- | --- | --- |

| `DELETE` | `/api/v1/devices/:deviceId` | → `204` |

Push is only attempted when the recipient has **no** open socket.

## Realtime (WebSocket)

`GET /api/v1/realtime` (upgrade). `GET /api/v1/realtime/info` lists the frames.

**Client → server**

```json
{ "type": "auth",   "data": { "accessToken": "…", "deviceId": "…" } }
{ "type": "ping" }
{ "type": "typing", "data": { "conversationId": "…" } }     // ≤ 1 per 1.5 s per socket
```

**Server → client** (every frame carries `eventId` and `sentAt`)

| Type | Data | When |
| --- | --- | --- |
| `auth.ok` | `{ userId }` | After a valid `auth` frame. Nothing else is sent before it |
| `auth.required` | `{ reason }` | Bad/expired token — the socket is closed (4003) |
| `pong` | — | Answer to `ping` (the client also answers server pings) |
| `message.created` | message | New message for either member |
| `message.updated` | message | `spoken` receipt landed |
| `message.read` | `{ conversationId, messageIds, readAt }` | The other side read your messages |
| `conversation.updated` | `{ conversationId }` | Consent or chat metadata changed |
| `peer.updated` | `{ userId, displayName?, allowsSpeak? }` | Rename or consent change |
| `presence.updated` | `{ userId, online }` | A chat partner opened/closed their last socket |
| `typing` | `{ conversationId, userId }` | The other member is writing |
| `error` | `{ code }` | `malformed_frame`, `unknown_type`, `auth_timeout` |

Rules: authentication is required within 10 s (otherwise close 4001); 45 s heartbeat;
64 KB max frame; the socket is a *fast path*, never the source of truth — everything is
also available over REST.

## Versioning & compatibility

* The prefix `/api/v1` is the compatibility boundary; fields are only ever added.
* Installed clients call `GET /api/v1/server` first, so a future breaking change can be
  detected instead of silently mistranslated.
* Clients tolerate unknown fields and treat every field except identifiers as optional.
